What this is good at

• Wizard enforces a pre-flight check — you literally can't reach Review without seeing the Evidence step
• Generous real estate for evidence work (full-width content + 360px panel)
• Letter is visible while you manage evidence — sidebar persistence is genuinely useful

What it's bad at

• 80% of letters don't need evidence at all — the step is dead weight for sick-leave, holiday requests, etc.
• You can never escape the visual flinch — even if the layout matches, the user notices "I'm on a different page now"
• Mobile: forces you through a wizard step that's just a stacked column of cards on small screens
• Two surfaces (popover + sidebar) on the same page is inherently confusing

Option B · Drawer + Finalise as the last step

Evidence becomes a tool, not a step. A dedicated drawer button lives in the top toolbar (always one click away). The wizard becomes Edit → Review → Finalise — three steps that map to the actual mental model: write, check, ship. A handoff card asks about evidence completeness when moving Edit → Review. Proposed

Steps: 3 (Edit · Review · Finalise)Evidence surfaces: 1 (drawer only)Free real estate: the right rail is whatever the current step needs

Option C · Hybrid — the pinnable evidence rail

Same wizard as Option B: Edit · Review · Finalise (no forced Evidence step). But the evidence drawer can be pinned — converting it from a transient overlay into a persistent right rail that replaces the AI agent panel. Two modes for evidence, user picks based on their workload. Proposed hybrid

Wizard: 3 steps (Edit · Review · Finalise) Evidence states: floating drawer OR pinned rail User chooses: light workflow vs heavy workflow per-draft

Mode 1 · Floating — quick reference insertion

Default state. Click the Evidence button in the toolbar → drawer slides in over the editor. Pick an item, insert at cursor, drawer closes. For when evidence is a side-quest to the prose you're writing.

The two modes — what flips between them

Per-draft state, persisted to localStorage. Returning users land in whichever mode they last used. For evidence-heavy template types (tribunal, grievance, settlement) the default could be Pinned; everything else defaults to Floating.

Floating · default

Drawer overlays the editor
When: light letters, quick reference insertion, narrative-first workflow.
Trigger: click toolbar Evidence button → drawer opens.
Closes: after Insert, on Esc, on backdrop click, or via × close.
AI agent rail: visible (drawer overlays it).
Width: 560px sheet.

Pinned · heavy work

Rail replaces AI agent
When: evidence-heavy letters, 5+ exhibits, tribunal-bound matters.
Trigger: click "Pin →" inside the drawer header.
Persists: across navigation. Survives reload via per-draft state.
AI agent rail: collapsed; can be summoned via inline button if needed.
Width: 380px column.

The handoff card still fires on Review →

Identical to Option B. The check runs regardless of whether evidence was managed via floating drawer or pinned rail. Same nudge: "you have N unused exhibits."

Why C wins over A and B

From A — we keep the persistent rail (Pinned mode) so heavy evidence work has full space. From B — we keep the clean 3-step wizard (Edit · Review · Finalise) and the drawer for transient lookups. The user picks their workflow per-draft. Nothing is forced.

Light letter — holiday request

Workflow: stays Floating. User doesn't even notice evidence as a concept. Skips drawer entirely. Goes Edit → Review → Finalise in 3 clicks. Time to ship: ~2 minutes.

Medium letter — grievance

Workflow: writes prose, clicks Evidence button, drawer slides in, inserts 3 refs, closes drawer, continues writing. Handoff card on Review nudges if any are unused. Time to ship: ~10 minutes.

Heavy letter — tribunal claim

Workflow: opens drawer, clicks Pin →. Evidence rail stays visible for the entire drafting session. Picks/inserts/cross-references 15 exhibits without context-switching. Time to ship: hours, but every minute spent inside the editor instead of bouncing between routes.

Honest take

C wins on 9 of 11 dimensions. The two it ties on (risk of skipping evidence; discoverability) it matches B, not loses to A. The cost: one extra piece of state (pinned/floating) and one extra UI control (Pin button). Worth it.

Why C beats both pure options: users self-select their workflow. The default (Floating) optimises for the 80% of letters that don't need persistent evidence work. The escape hatch (Pinned) gives the 20% the real estate they need without forcing it on everyone else.

Migration path (4 commits):

  1. WizardChrome: re-add Finalise as Step 3. Wizard becomes Edit · Review · Finalise for all drafts.
  2. EditorToolbar: dedicated Evidence button with count badge. Clicking opens the drawer (Floating mode).
  3. EvidenceDrawer: add a Pin button in the header. When pinned, the drawer-shape mounts as the Edit-step right rail (replacing the AI agent panel). Persist `evidencePinned: true` per-draft in localStorage.
  4. Deprecate `/editor/:id/evidence` route — 302 redirect to `/editor/:id?openEvidence=1` so old bookmarks still land somewhere useful. Keep EvidencePanel.tsx for one release in case revert is needed.
