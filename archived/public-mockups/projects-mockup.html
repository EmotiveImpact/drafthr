Projects (Matters) — concept + four layout variants

After ~10 drafts a flat list breaks down. Every letter clusters around a thing — a person, a case, a hiring cycle. Below: the concept, then four UI directions for surfacing the cluster. Tab through, then pick one.

The Matter

A Matter is a named container for letters that belong together. Most letters won't need one. The ones that do (a discrimination claim, a PIP, a redundancy round, a hiring cycle) cluster better when they sit under a shared name.

Employee mode

Auto group by Employer — every letter you ever wrote to Acme Holdings sits together.

Manual tag a Matter — e.g. "Acme discrimination claim 2026 Q1" ties together your grievance, appeal, ACAS EC notice, tribunal cover.

  • Acme discrimination claim 2026 — grievance · appeal · ACAS EC · tribunal cover
  • BigCorp resignation 2025 — resignation with grievance · withdrawal

HR / Employer mode

Auto group by Person — every letter about James O'Connor sits together over the years.

Manual tag a Matter — e.g. "James's PIP 2026 Q2", "Engineering hiring round Spring 2026".

  • James O'Connor — PIP 2026 Q2 — PIP letter · mid-point check-in · outcome
  • Spring 2026 hires — 12 offer letters · 3 right-to-work · 2 contract amends

A · Sidebar tree (Notion-style)

Hierarchical sidebar · matters expand inline

Matters live as expandable nodes in the existing sidebar between Watch and Recent drafts. Click a matter name → main canvas shows that matter's letters. Click a letter → opens it. Matches the navigation pattern users already know (Recent drafts uses the same convention).

B · Project switcher (Linear-style)

Sidebar shows app-wide nav · matter picker lives in the topbar

Sidebar stays clean (no nested tree). A picker at the top of the main canvas lets you switch matter — like Linear's project picker or Notion's workspace switcher. The selected matter "owns" the rest of the page: all of Home, Calendar, Activity filter to it.

WinsZero setup — works on day one with no concept to learn. The grouping you'd naturally want already happens. "Make this a Matter →" upgrades a group into an explicit named matter when the user is ready.
CostsAuto-grouping by name string is fragile — typos / casing differences break clustering. Cross-employer / cross-person matters (e.g. an industry-wide matter) don't fit naturally.
My recommendation Ship D first (zero-setup auto-grouping) — it's the smallest change and immediately makes Home useful at 10+ drafts. Then layer A on top — the explicit Matter concept lives in the sidebar tree once the user opts in by clicking "Make this a Matter →". That gives you the cheap UX win now and the power-user feature later, with one mental model bridging them.

Variant C (two-pane) is best when you have 50+ matters per user — that's the "law firm scale" feature, not v1. Variant B is a strong alternative if matters feel too central to want them ambient in the sidebar.
