# Private evidence and saved exports

## Implemented

- `workspace_files` owns metadata in Postgres: tenant, originating draft, uploader, purpose, filename, content type, size, SHA-256, source draft revision, storage provider, readiness and timestamps. Export rows additionally capture the source draft snapshot.
- Prepare requires an authenticated tenant-pinned writer and the exact saved draft revision. A reused upload ID cannot be assigned new content. Evidence is limited to 10 MB; exports to 25 MB. SVG, HTML and executable types are not accepted as evidence.
- Hosted uploads use the installed Vercel Blob client with an exact-path, exact-type, size-limited, ten-minute token. Overwriting is forbidden. Files must be in a private Blob store. The application never exposes a public file URL.
- The completion request reads the private object, bounds actual bytes, verifies size and SHA-256, then commits readiness and the audit event in one database transaction. Pending uploads are not downloadable and do not appear as completed exports. Completion is idempotent.
- Authenticated downloads pin the workspace and return attachment, no-store, nosniff and sandbox headers. Export bytes remain unchanged after draft edits or soft deletion. Evidence references can be shared by copied drafts in the same workspace; an active copy preserves download access after source soft deletion.
- Finalise saves the artifact before downloading or adding a successful export event. Exported letters reads the authoritative file list. Manual “marked sent” events are not exported files and do not prove delivery. Historical events cannot recreate their original bytes.
- New evidence uploads store `fileId`, `fileSize` and `fileSha256` rather than file bytes in a draft. Export renderers resolve these references for the resulting self-contained document. Image previews use temporary object URLs, not persistent browser storage.
- Section-editor image-file paste/drop and the image toolbar now share the private upload path. Inline evidence insertion uses a strict tenant-pinned file URL; sanitization permits only this exact route or legacy safe raster data URLs, never arbitrary image hosts. PDF/Word/ZIP preparation resolves inline references transiently and refuses unlinked or wrong-workspace images. Late uploads cannot write into a changed workspace or stale/destroyed/read-only editor; successfully stored evidence remains available for reinsertion when the editor changed.
- Preview, PDF and Word now share numbered attachment/exhibit HTML. Finalise offers an on-demand read-only preview (Pagedly remains the editing surface), resolves private images transiently, and applies accepted suggestion changes for export. Cancelled/old-workspace reads cannot render a late preview. The sidebar now identifies A4 paper rather than claiming every letter is two pages.
- A guarded local adapter writes private files outside the repository under `DRAFTHR_LOCAL_FILE_ROOT`. It requires the local WorkOS emulator and dedicated loopback Postgres configuration and refuses production/preview environments. It is not a hosted Blob fallback.
- Migration 0023 supports staged legacy-file imports without placeholder drafts. Staged metadata is pinned to tenant, uploader, import token and intended draft. Normal file lists/downloads exclude unattached imports; only the original uploader with the token can verify staged bytes. A draft save validates staged ownership and attaches the file in the same transaction as the draft and audit event. Failed transactions leave the file staged, not falsely published.
- Browser import extracts supported evidence data URLs and inline images from current sections, version history and pending edits, stages the private bytes, verifies metadata and byte hashes, and then writes reference-only snapshots. Stable IDs make retries reuse the same files. Verification uses authenticated 1 MB ranges; original browser records remain until the full rewritten graph is verified. Invalid/unsupported files fail visibly rather than being stripped.
- Migration 0024 adds `workspace_assets` for reusable branding and template images independent of a draft. Uploads pin the workspace, enforce writer roles, record pending metadata, verify private bytes, and commit readiness plus audit atomically. Content-addressed retries do not overwrite existing objects. Database mode uses the guarded local adapter for development and never falls back to embedded browser bytes. Existing authenticated tenant image URLs remain readable through a checksum-verified compatibility path until imported.
- The importer now normalizes profile/draft letterheads and signatures, custom-template section images, and existing reusable images in draft histories. It verifies uploaded bytes before the rewritten graph is saved, deduplicates within the import, and retains originals on failure. It only fetches strict same-workspace private routes; unsupported external references stop visibly. Settings JSON import shares this path and applies validated fields in one update without importing credits or permissions.
- Private reusable images resolve transiently for preview/export and are allowed through strict HTML sanitization. Failed private-image reads stop exports rather than silently omitting branding. Image upload controls reject stale/unmounted completions. Settings' Save waits for database acknowledgement; the old device-clear action and simulated permission control are disabled/hidden in database-workspace mode.
