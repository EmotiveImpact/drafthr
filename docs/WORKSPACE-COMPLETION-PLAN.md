# Workspace completion goal

Finish the database-backed employee → matter → draft → review → export → reopen workflow without redesigning the app. A record is saved only after a durable server acknowledgement. Local recovery data is never silently discarded or imported into a different workspace.

## Ordered delivery checklist

- [ ] Tenant-scoped employee, matter/participant, task, event and template CRUD, with per-record revisions, input validation, authorization and safe deletion.
- [ ] Database-backed personal/workspace settings; server permissions are never taken from browser settings.
- [ ] A single coordinated workspace hydration/save lifecycle, with dependency ordering, conflict recovery, pending/failed states and sign-out/switch guards.
- [ ] Explicit, repeatable legacy import preserving all relationships and both sides of conflicts; no automatic cross-workspace adoption.
- [ ] Private evidence/files and immutable exported artifacts with metadata, ownership and authenticated retrieval; distinguish exported from sent.
- [ ] End-to-end workflow on fresh browser contexts and a real isolated database; offline/reconnect, stale writers, deletions, session changes and tenant isolation.
- [ ] Hosted staging with the intended Vercel/Neon/WorkOS configuration and real-provider auth tests.
- [ ] Launch gates: delivered email, tested billing, backup restore, monitoring, access controls and owner-reviewed privacy/retention/operating requirements.

## Boundaries

- Preserve the current design and existing uncommitted work.
- Use additive, versioned Drizzle migrations. Test on the disposable local database, then an isolated hosted branch. No production migrations or public launch during implementation.
- Do not enable a partial database cutover for customers or claim cross-device safety early.
- Keep provider provisioning and business-owner decisions explicit. Passing local tests is not production sign-off.
