How should regenerate work?

Today the Regenerate button re-runs the same prompt with the same wizard answers, so output looks the same. Two ways to fix it. Below is what each looks like in the editor, then a recommendation at the bottom.

Option A · Per-section refine instructions

Refine this section.

The existing Regenerate button on every section header opens a tight popover with a single textarea: "Optional instructions for this regeneration…". Submit → only that section regenerates, with the user's instruction appended to the existing section prompt as USER REFINEMENT:.

Quick chips below the textarea preset common asks: more formal, shorter, add specific clause, cite ACAS, etc.

Strengths: in-place, fast (one popover), ties refinement to a specific section, immediately useful, no new mental model.
Limits: can't say "rewrite the entire letter in tribunal-ready tone", only operates on one section at a time, no history of past refinements.

Option B · Right-rail AI chat (Contracts-style)

An AI agent for the whole letter.

A fourth right-rail tab — AI — joining Compliance / Comments / People. A chat thread scoped to the current draft. The agent has read access to every section and the wizard answers, and write access via tools (regenerate section, edit section, add clause, change tone).

The user types freeform: "rewrite section 2 to be tribunal-ready", "make the offer warmer", "add an IP-assignment clause to body", "summarise this letter for my lawyer". The agent replies, applies the change, and the section visibly updates.

Scope chips above the input: whole letter / section / selection. Common asks pre-filled as quick buttons: + make formal, + tribunal-ready, + add clause.

Strengths: handles multi-section commands, freeform asks, history of instructions per draft. Becomes the front door to every AI capability — not just regeneration but also "draft a counter-offer", "summarise for counsel", etc.
Limits: bigger build (chat state, scoping, tool plumbing). Discoverability: not every user thinks to chat; many will keep clicking Regenerate. New mental model.

Recommendation

Build both. They serve different intents.

Option A is the right answer for "this paragraph isn't quite right" — 80% of regeneration intents. Inline. Fast. Two clicks. Discoverable because it lives on the existing Regenerate button.

Option B is the right answer for "rewrite the whole letter in a different tone", "add a clause about IP across the relevant sections", or "summarise this for my counsel" — multi-section, freeform, conversational. It also becomes the surface for future AI capabilities (draft from clause library, compliance audit, counter-offer generator) without us having to design a new affordance each time.

Build A first (it's a half-day). Use it as the immediate fix for your "regenerate gives me similar output" frustration. Build B alongside or right after — it doesn't conflict with A. If we built B alone we'd lose the in-place affordance and force users into a chat for every tweak; if we built A alone we'd cap users at single-section refinements forever.

  • Order: A first (immediate value), B second (the big upgrade).
  • Scope of A: textarea + 4 chip presets + applies to one section.
  • Scope of B: chat thread, scope chip (whole / section / selection), tool-use to apply changes, undo per turn.
  • Future-proofing: B becomes the home for "Edit details" (re-open the wizard fields without leaving the editor) too.
